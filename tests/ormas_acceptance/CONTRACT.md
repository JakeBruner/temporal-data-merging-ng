# Offline Ormas repository readiness auditor

Implement tools/ormas_readiness.py using Python 3.12 standard library only and document it in tools/README.md. This is an offline diagnostic aid, not a gateway client or authoritative qualification decision. No network, installations, writes, authentication, wallet actions, heartbeat refreshes, or server modifications. Do not import tensorbox_spec or an Ormas package. Frozen tests are outside the candidate process.

CLI: python3 tools/ormas_readiness.py --repo PATH --catalog FILE --profile ID [--inventory FILE] [--capacity FILE] [--now UTC_TIMESTAMP]. --now defaults to current UTC. Timestamps must be timezone-aware ISO8601; Z is accepted. Emit exactly one JSON object, no traceback or raw input on stdout/stderr. Repeated identical explicit inputs produce identical output. All reports include schema_version=ormas.readiness-report.v1, ruleset=2026-10-04.1, live_admission=not_established. Unknown future catalogs are not silently supported. Exit 2 for invalid CLI/catalog/inventory/capacity JSON input, with error.code fixed (input_invalid, input_too_large, catalog_invalid, profile_unknown). Otherwise exit 1 if repository or capacity is blocked, exit 3 if either is unknown, exit 0 if repository compatible and capacity not_obviously_blocked. Invalid input precedence wins. Never echo arbitrary malformed data, credential-bearing URLs, paths supplied by a user, env values, or unknown capacity fields. Fixed issue codes and fixed explanatory/remedial prose suffice; package names may be omitted.

Catalog is outcomes.support-catalog.v1, revision 2026-10-04.1, verifier_compiler_sha256=6208cd158fe74d2e71f0917f85bd761c7df118b1b930a3280353412de7add9ff. profiles is a list with unique profile_id, status, lock_format and limits. Profile limits max_files/max_bytes and optional source_max_bytes must be positive integers (bool is not integer). Unsupported revision/compiler/lock format/status(planned) yields repository unknown with unsupported_catalog_rules or profile_unavailable as appropriate. Unsupported catalog rules or an unavailable profile short-circuit repository rule evaluation after invocation input validation, so repository remains unknown; do not apply old rules to a future contract. Catalog malformed shape => catalog_invalid; absent ID => profile_unknown. Digest is sha256: followed by SHA256 of UTF8 json.dumps(catalog,sort_keys=True,separators=(',',':'),allow_nan=False) using the default ensure_ascii=True. Include profile_id and catalog_digest in output. Ignore harmless extra catalog fields but include them in digest. Empty/malformed profile lists and duplicate IDs are invalid.

repository = {status: compatible|blocked|unknown, detected_locks: sorted list of existing root package-lock.json/package.json/pnpm-lock.yaml/requirements.lock/yarn.lock, source:{files:int|null,bytes:int|null,inventory_mode:provided|git|unavailable}, environment_names: sorted unique names, findings:[{code: fixed_code,...}]}.

Inventory JSON is a list of relative POSIX paths. De-duplicate entries. Reject absolute, empty, dot, dotdot, .git component, or backslash paths as input_invalid before touching them. With --inventory inspect exactly supplied paths; do not invent completeness. Without it, use git ls-files --cached --others --exclude-standard -z if Git metadata and executable exist, otherwise inventory_unavailable and source null, repository unknown unless another known blocker exists. Preserve tracked files even if ignored, exclude ignored untracked files as Git does. Count all unique regular supplied/Git paths and sum lstat sizes, never follow a symlink at any component. Symlink => repository_symlink, missing/unreadable/nonregular path => inventory_path_unavailable (unknown), max_files exceeded => source_file_limit, bytes exceeded => source_byte_limit. Limits are inclusive, source_max_bytes overrides max_bytes for the SOURCE only; max_bytes may be an artifact limit. Do not prune media to hide oversize source. A known blocker outranks unknown. Fixture sparse files count by logical size. Inventory paths whose first component is .venv, venv, node_modules, .ormas-install, or .ormas-cache are known blockers source_installed_artifacts_refused; do not silently delete or hide a tracked installed artifact. Inspect root lock/environment files safely even if absent from inventory; avoid following symlinks for those too. Root repo must be an accessible real directory, not a symlink. Root .env and .env.example yield only syntactically valid [A-Za-z_][A-Za-z0-9_]* variable names from assignments, with optional export prefix and surrounding whitespace; skip comments, preserve unique names sorted, never print any assigned values. Read at most 4 MiB per catalog/inventory/capacity/manifest/lock/env file. Oversized invocation JSON is input_too_large; oversized repo diagnostic inputs => repository_input_too_large blocker. Do not read source file contents for size accounting.

For npm-lock-v3 require root package.json and package-lock.json (missing => npm_lock_required), strict JSON manifest dict, lock dict with integer lockfileVersion=3 and nonempty packages dict containing dict root '', <=4096 entries. Invalid shape => unsupported_node_lock. dependencies/devDependencies/optionalDependencies in manifest default {}, must be dict of exact numeric X.Y.Z strings (no ranges/prerelease) => node_direct_dependencies_must_be_pinned. Their dicts must exactly match lock root corresponding groups => node_manifest_lock_mismatch. Every packages value dict, no truthy link => unsupported_node_lock. Every nonroot resolved must be HTTPS registry.npmjs.org with no username/password/explicit port/query/fragment. integrity must be sha256 or sha512 with strict base64 and decoded algorithm length => unsupported_node_registry_or_integrity (bad URL/grammar) or invalid_dependency_integrity (bad decoding/length). Catch URL parsing failures as blockers, never echo URLs. A root pnpm lock with no npm lock adds pnpm_adapter_unavailable; a simple safe root lockfileVersion scalar may be reported but full pnpm graph need not be parsed. No claim that changing package managers or deleting assets is automatically safe.

For pip-hashes-v1 require root requirements.lock (missing => pytest_lock_required). Ignore blank/comment lines. Other lines must match exactly name==version followed by one or more space separated --hash=sha256:64_lowercase_hex tokens, where name pattern [A-Za-z0-9][A-Za-z0-9_.-]*, version pattern [A-Za-z0-9][A-Za-z0-9.!+_-]*. Invalid syntax => unsupported_python_lock. At least one pin, <=512 pins, name pytest case-insensitive present => pytest_lock_required otherwise. Offline pins do not establish wheel availability or installation success.

Capacity optional local summary schema ormas.offline-capacity.v1 (NOT an Ormas gateway wire schema): catalog_digest, profile_id, observed_at UTC timestamp, project_admitted bool, qualified_miners nonnegative integer, miners_with_cells nonnegative integer <= qualified_miners, qualified_checkers nonnegative integer, required_validators positive integer. Optional occupied_cells/busy_miners are ignored: busy cells alone do not establish enqueue qualification failure. No other fields ever copied to report. Missing summary => capacity_missing/unknown; any missing/invalid field (including bool counts, negative counts, invalid timestamp/schema) => capacity_invalid/unknown, not zero. A structurally valid summary with catalog/profile mismatch => capacity_catalog_mismatch/capacity_profile_mismatch unknown. Age in [0,60] seconds inclusive is fresh; >60 => capacity_stale unknown; <0 => capacity_future unknown. Interpret blocker counts only after schema/matches/freshness valid. project_admitted false => project_not_admitted; qualified_miners=0 => no_qualified_miners; miners_with_cells=0 => no_qualified_cells; qualified_checkers<required_validators => insufficient_checkers, all blocked. Fresh matching admitted positive counts/checkers => not_obviously_blocked. Aggregates do NOT prove independent ownership, credential binding, an eligible selected plan, or live availability. Always live_admission=not_established. capacity = {status:unknown|blocked|not_obviously_blocked,findings:[{code,...}]} with stable sorted unique codes. All findings in repository likewise sorted and unique. Fixed prose should explain remediation/limitations. README must describe invocations, inventory coverage, UTC freshness, exit codes, offline limits, secret handling, and why unsupported pnpm/absent Node supply are distinct.
